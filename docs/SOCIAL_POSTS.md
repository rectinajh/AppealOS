### English（主发布版）

We built **AppealOS Runtime** for #AllThingsAgenticHackathon (track: The Taskmaster).

Platforms already use algorithms to judge us. AppealOS turns a suspension notice into one durable, user-owned case: after a single scoped mandate, the agent submits the appeal, handles one authorized evidence request, tracks the response, and verifies the final account state directly.

The safety boundary is the product: **models interpret, code authorizes**. Analysis consent and the external-action mandate are separate. The demo runs on a synthetic MockDrop simulation — no live-platform integration claimed.

- 🧠 Gemini 3.5+ for structured interpretation
- 🛠️ Google ADK for typed tools
- ☁️ Cloud Run + Firestore + Pub/Sub for the workflow
- ✅ Receipts before celebration; verified `ACTIVE` before success

## 版本 B · 短线程 / Short thread（想多展开时用）

### English thread

1/5 One automated decision can suspend an account and cut off income before you understand the allegation, deadline, or evidence. The appeal process is a contextless form. #AllThingsAgenticHackathon

2/5 **AppealOS Runtime** makes that process one durable, user-owned case. One scoped approval → submit appeal → handle one authorized supplement → track response → verify the account state directly.

3/5 The agent is safe by construction: `AnalysisConsent` reads internally, `AppealMandate` writes externally. **Models interpret; code authorizes.** Deadlines, scope, idempotency, and receipts live in deterministic code.

4/5 The hackathon proof runs on a synthetic **MockDrop** simulation and reveals a cellular handoff was mistaken for location fraud: `SUSPENDED → APPROVED → ACTIVE` — with the account verified before we celebrate.

5/5 Built with Gemini 3.5+, Google ADK, and Cloud Run. No live-platform integration claimed; synthetic data only. #AllThingsAgenticHackathon
